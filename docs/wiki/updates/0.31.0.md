## 发射签名与原生行为

发行反射确认`FireComponent.CheckRayHit(AabbRay2DResource,int,int,bool)`，新增`combatTargetsOnly`默认false。旧三参数源码可重新编译，但旧DLL对三参数方法的绑定不能自动匹配四参数版本。超级机枪的[FireRayQuery](../../../examples/SuperGatling/FireRayQuery.cs)缓存解析三/四参数签名，并显式传false保留原查询语义；这不是全部宿主API的通用兼容层。

源码投手优先查询可攻击的僵尸/敌方植物，维持范围、阵营、碰撞标记和行限制；无有效战斗目标时仍按原路径处理障碍物。普通射线查询与投手优先查询不能混用，也不应仅为预览改写宿主索敌。标准抛射公式未发现变化；`pvzhe-0.30-standard`是既有行为配置标识，不因发行变更批量改名或丢弃已有方案，是否沿用由发行/校准结果约束。

`BulletFieldSpawnOverrides`新增`yOffsetTargetOverride`、`yOffsetDurationOverride`；`TowerDefenseCharacterEventProjectileSplit`新增`spreadDuration`。逻辑行可在出生时锁定，画面再从命中点向目标行展开；这与倾斜速度造成的扇形不同。MagicPea当前资源设置forwardOffset=0、spreadDuration=0.25，不将这组数值当成所有弹药默认。

Node与BulletField命中路径均补齐`ProjectileEffectsBlocked`对hitTargetEventList的限制；“伤害成功但没上控制效果”可能是宿主防具规则，不应无条件补加Buff绕过。该方法现在可被角色覆写。树桩兼容优先查注册表/`CanPassNormalStump`，不按弹药名字猜测。

## 选卡、阳光与多格外壳

`TowerDefenseLevelSeedBankConfig.choosePacketLimit`及JSON字段`ChoosePacketLimit`：-1沿用已解锁槽数；CHOOSE模式下0～16是上限，最终取已解锁槽数与上限的较小值，不是强制解锁这么多槽。PRESET等模式不使用该上限。不能固定假定7槽或把16当作所有关卡容量。

`TowerDefenseLevelSunManagerConfig.maxSun`及Sun配置的`MaxSun`：-1不限，0是有效上限，仅限制最大余额，不自动将合法的负数惩罚归零。Credit、退款、读档和旧接口入账均可能被截断；验收应比较实际余额及生效增量，不能一律断言“请求50就必增50”。默认值仍-1，旧配置不必为兼容补字段。

多格Footprint支持外壳：`Surround`、`ReplaceSurrounds`、`StrictCenter`，能力键`wide-plant-surround-transaction-v1`。外壳配置需有SURROUND类型/覆盖槽，不能同时要求替换底座或底座高度提供器；普通单格植物仍不需要注册Footprint。StrictCenter在边缘拒绝而非自动夹入；整行宽度有例外。接口存在与能力声明不代表所有平台已经验收。

## 状态、阶段与视觉

`XWModCombatPoints.EffectAdmission`为主机Modifier，数据`XWModEffectAdmission(Target,Key){Blocked}`。常规Gameplay AddBuff在进入或刷新前检查，Target/Key不能改变；Blocked只能由false变true，不能解除其他Mod的拒绝。不是SaveRestore/NetworkRestore的通用拦截器，也不应假定所有特殊状态刷新分支都经过它。

全息角色是否接收Buff由`AffectsHologram`决定，默认false；需要支持的增益显式开放。`CanRunAbility`增加正式战斗、非编辑预览及运行状态条件。`GetLogicTimeScale`区分谜题待机的动画冻结与逻辑计时；复用宿主计时服务，不用动画timeScale=0推断整套逻辑应停止。

新增`BattleEventBus.OnPlantManuallyPlanted`只代表卡片成功种植，不包含召唤、读档和网络重放；不要用一般角色生成通知替代手动种植语义。僵尸计数可排除指定阵营，最终波次等待也考虑敌我；“剩余敌人”与“所有僵尸对象”继续分开定义。

外部AdobeAnimate视觉现在继承本体纵向裁剪，需在水面等场景核验附加冰块/部件的显示。原版角色资源存在目录迁移（如GarlicWood/HypnoPot/Sealeaf转入HybridPark），使用注册键及当前PCK/remap定位，不继续拼接旧物理路径；本轮未发现模板C#中完整res://字面引用被删除，不代表任意用户资源都无需检查。

## 自动化测试：失焦暂停

2026-10-30对当前发行DLL与PCK静态核验：`Asset/Config/Save/ConfigInit.json`的`Backgrounder`默认为false。`BattleOption`的`%BackgrounderCheckBox`读取该键，`BackgrounderCheckBoxToggled`调用`SetConfigValue("Backgrounder", toggledOn)`及`SaveGameConfig()`；true表示后台运行，不是开启失焦暂停。

`TowerDefenseControlNew._PhysicsProcess`在isGameRunning、非waitPause、非联机、场景树未暂停、Backgrounder=false且窗口失焦时调用OpenGamePauseDialog，创建`Pause`弹窗。每物理帧重新读设置，因此无需为此设置重启进程；已打开的暂停弹窗不会仅因修改设置自动关闭。手动Pause输入独立检查，不受Backgrounder条件控制。

隔离测试驱动应在GameSaveManager及配置就绪后、正式进入对局前保存`GetConfigValue("Backgrounder").AsBool()`原值，调用`SetConfigValue("Backgrounder", true)`并读回。setter会标记配置脏并启用处理，不能假定只改内存、绝不会写盘；临时测试结束恢复原值并按需要SaveGameConfig，崩溃后下次启动检查遗留值。专用隔离测试配置可明确保留true，不修改日常用户目录。人工可用宿主对应复选框，节点身份如上，未在本轮确认其中文标签。

证据范围：以上为发行实现与配置静态核验，本轮未启动游戏，未将切换焦点后继续推进标为实测；旧控件模式、后台帧率及联机行为不据此推定。运行时仍需按[测试会话准备](../../../.agents/skills/pvzhe-mod-verify/references/test-session.md)记录失焦前后状态并核验手动暂停保留。本地分析记录在.work/focus-review，不提交发行反编译内容。
