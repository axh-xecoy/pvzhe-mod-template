# 版本迁移流程

仅在已明确要求升级模板后读取。路径全部来自当前用户输入；相对输出以模板根目录为准。缺少新版源码和发行版时先询问输入，不从旧报告中的本机路径推断新路径。

## 保存与识别基线

- 读取 README、docs/compatibility.md、docs/validation.md、docs/wiki/README.md 及旧基线主题页、清单、项目文件及相关工具/Skills；检查工作树，保留既有未提交修改，不重置或覆盖它们。
- 新版 prepare 会覆盖 .work 中的报告和引用。执行前将已有 release/api/pck-index/reuse-catalog 报告及必要对比资料保存到新的本地迁移目录，如 `.work/migrations/<迁移标识>/before/`；已有目录不覆盖。记录模板 Git 提交与未提交状态。旧发布包不在时如实注明不能重验旧版，版本控制中的说明不能冒充旧 DLL 证据。
- 从用户给出的目录核对目标。发行版检查 EXE/PCK/运行时对应关系、发布版本、引擎、目标框架与摘要；源码检查项目、清单、版本配置、提交/分支及 Mod 相关实现。多个候选发行版或目标版本含糊时询问，不能任选。普通补丁也可能改变接口，不能只按版本号大小推断兼容。

## 选择分析输入

| 输入 | 可以进行的分析 | 验收边界 |
| --- | --- | --- |
| 完整发行版 | 未支持发行先 `prepare --analyze-only --game-dir '<新版目录>'`，在独立报告目录索引/提取和反射 DLL；必要时本地反编译 | 适配完成、更新兼容声明并正常prepare后，可以完成玩家构建和真实运行验收，无需源码 |
| 游戏项目源码 | 搜索 Mod 接口、加载器、资源注册、配置和生命周期；对照旧证据与模板实际调用 | 不将源码工程设为玩家依赖；缺少发行版时只报告静态/构建覆盖，继续请求发行版完成运行验收 |
| 两者都有 | 源码用于解释机制，发行版用于确认实际接口、资源与行为 | 记录版本/提交不一致；新版支持结论绑定实际验收的发行版 |

首次读取源码时遵循用户所给目录的适用工作约定；只分析，不因升级模板去修改或编译宿主工程。确需额外宿主工作时先说明其必要性与范围。工具因格式/API变化无法运行时，先保存原始诊断，再从新版输入核对并适配工具；不能伪造旧接口、跳过摘要或验收来获得“通过”。

## 建立影响表，按证据适配

优先追踪模板及受支持示例实际使用的能力，而不是遍历所有宿主实现。公共 API 签名不变也需检查语义、默认值、事件顺序、资源内容及权限是否改变。

Mod API数字不变仍需比较完整方法签名：增加可选参数不自动保留旧DLL绑定。成员种类变化（字段↔属性、静态性、const内联等）同样破坏旧绑定，并可能在Mod侧被try/catch静默吞掉；有旧已编译包时用其对新宿主做一次加载回放，新构建通过不能证明旧包可用。改适配时先按目标发行重新编译，确需保留旧签名才做窄适配；在真实裁剪运行时执行，不能仅以桌面.NET单测通过证明BCL类型/重载可用。若宿主只记录回调失败的外层异常，用一次定向诊断展开InnerException，修复确定原因后只重验受影响链路；不反复完整启动猜测。

| 比较项 | 可能需要同步的位置 |
| --- | --- |
| 引擎/.NET/平台、PCK 格式与发布目录 | global.json、csproj、prepare/HostProbe/PCK 工具、开发环境说明 |
| 清单 schema/API、入口契约、依赖与打包协议 | mod.json、示例清单、入口、构建允许名单和包检查 |
| Hooks/Presentation/Content/Game 等接口及生命周期语义 | 实际调用点、Adapters、场景作用域、异步回调和对应制作配方 |
| 资源路径、UID、导入映射、节点结构、注册键 | catalog、宿主场景接入与组件复用目录；禁止复制原版素材来掩盖引用失效 |
| 设置、数据 schema、存档和进度行为 | 设置/数据接入与迁移策略、参数说明及恢复验收 |
| 关卡结构、目录身份、图卡、卡槽依赖 | 关卡解析/注册、自己的配置、关卡配方及示例验收 |
| 加载路径、启用配置、首次启动、日志和退出行为 | 安装/运行驱动、验证检查器、首次启动和排障参考资料 |

每项记“旧证据→新证据→影响→所需改动→验证”，无影响或未知也标明。优先在现有适配层处理变化，保持默认 Hello World 精简；不自动新增组件库、多版本分支或尚未支持的植物/角色能力。旧版是否必须继续支持，若会改变实现方案而对话未明确时询问；不默认宣传兼容全部旧版，也不静默丢弃已承诺支持的版本。

文档与 Skills 更新跟随最终实现：更新当前支持基线、命令、前置条件及资源/API依据；历史验收记录保留原日期和版本，另写新版记录，不把旧结果换个版本号。当旧问题是否已修复还未知时标为待核验，不删除原诊断或沿用旧结论。

## 同步版本化 Wiki

回归组织按 [验证执行策略](../../pvzhe-mod-verify/references/verification-strategy.md)：建立版本差异与受影响用例对应关系，检查器/报告离线验证，保持本轮输入与证据隔离；不得用旧版成功报告补足新版未测项。

遵循 [Wiki 维护规则](../../../../docs/wiki/maintenance.md)，只维护增量，不为每个游戏版本建立完整Wiki。每次明确升级模板都要评估影响，不以接口签名未变为理由跳过；未变主题保留原正文，在当前入口/差异表记录沿用来源和核对依据；变化章节写明确覆盖说明，必要时仅为受影响主题建新页。新版本目录不是必需；若需独立入口，只建简短overview/差异页，直接导航到各主题最终有效资料，不让读者逐版追溯。保留旧版原始验证记录，不复制正文或批量替换页头版本号。

按影响范围对照启动/场景状态、UI组件和节点、坐标命中、关卡入口、角色与资源注册键、战斗命令、设置存档及构建验收路径。影响表记录对应Wiki页和证据，无变化也说明核对范围。UI更新先比较目标区域控件清单：节点/动态创建入口、实例来源、锚点/缩放/层级、显隐赋值与阶段条件、动画和自动布局、PC/移动等模式切换、卡槽数量和金币等触发显示的范围及布局事件覆盖；来源为新版发行资料或用户提供且匹配的源码，公共签名不能替代行为分析。再按这些条件选择运行阶段验证尺寸和交互；截图未出现不能证明控件已删除。行为资料缺失时保留待核验，不能把旧占位改为可用空位。

新版未运行的项目标为静态核对沿用或待验证，不直接复制旧版实测标签；无差异的正文不因此重复撰写或要求整套重测。新增实测证据后更新适用范围、索引默认版本、README、Skills的主题链接和旧配方导航；只有源码时保持当前已验证基线入口，另列新版待验收说明。沿用旧正文的链接须通过当前入口明确目标版本适用范围及必要覆盖说明，不能绕过新版差异直接指向已失效的旧规则。

## 验收与停止条件

同步核对[卡池与种植](../../../../docs/wiki/0.30.0/card-pools.md)和SuperGatling案例：PacketBank覆盖/身份、分类与解锁数量/卡槽容量导致的自然分支、配置类及默认子系统资源、单格与Footprint区别、原卡/新卡对照。自定义验证接口与runtime_diagnostics错误规则随新版日志更新，仍要求业务结果；保留少解锁自动装卡和多解锁真实选卡两种前提。

涉及模式/导航时同步[导航Wiki](../../../../docs/wiki/0.30.0/mode-navigation.md)、mode-create、level-create章节参考及可选ModeNavigation配方。核对目录层级、场景名/加载表的公开扩展能力、Mod浏览根返回、管理器来源与页面重挂载；自己的页面不能作为独立场景注册的证据。重验受影响的章节路线、直接启动、返回/清理及模态/缩放，保留未测的进度与多人边界。

1. 工具变更运行项目规定的测试；用新版发布包重新 prepare/catalog、build/check，核对 DLL、清单、允许名单与产物身份。
2. 按 pvzhe-mod-verify 在独立测试目录安装启用并真实运行。默认 Hello World 回归；维护 FeatureLab 支持时回归其实际功能链路。驱动可能也需适配，不能以旧测试标记出现代替新版行为断言。
3. 在排除 .game/.work/dist/bin/obj 的干净模板副本中，只提供新版发行版，执行 README 所需的准备、构建、安装和运行；确认源码路径、机器路径、原版内容不被分发或成为玩家前置条件。Wiki/Skills 格式、相对链接、默认版本导航及适用流程也需检查。
4. 保留旧版支持时，用相应发行版重验所承诺的流程；缺失输入则列为未验证。记录源码分析、编译、静态检查、真实加载和功能行为各自覆盖程度。

输入不完整或目标不明确时继续独立分析，依赖缺失输入的步骤保持待定。未知 PCK/接口、启动崩溃或明确不兼容时保存证据，定位阻塞原因；不反复原样重试或修改玩家原存档。未完成真实发行版验证前，兼容报告必须标为部分完成，不能将目标版本写成已验证支持。

若继续维护已弃用的旧外部位置预览，且升级影响其逻辑尺寸、背景标定、组件外观或布局模式，应同步 docs/placement-preview.md、pvzhe-placement-preview 及实际适配资料。旧会话不可直接套用新版本坐标；保持用户绝对位置语义，不以升级为由自动引入避让。

资源缓存迁移核对game_cache提取器版本、PCK/宿主DLL摘要和依赖解析；新prepare切换身份目录，不覆盖旧证据。预览PNG还绑定当前Mod DLL及配置/图片摘要；版本、组件或捕获规则变化后重新产生干净背景/透明渲染，不能只给旧图片盖新摘要。长期协议见 [缓存与捕获](../../../../docs/resource-cache-and-capture.md)。

升级涉及旧外部位置预览或资源捕获时，重新核对捕获就绪条件（阶段、模式、槽数、稳定矩形）与显隐刷新/动画的抑制范围，记录捕获失败诊断及恢复规则。同步窗口拉伸、父层/锚点与输入映射；用户确认位置在参考画布保持忠实，宿主缩放继续生效，不能只验证单窗口数值相等。详见 [捕获协议](../../../../docs/resource-cache-and-capture.md) 与 [位置落地](../../../../docs/placement-preview.md#忠实落地)。

迁移构建器时保留默认HelloWorld与FeatureLab隔离，并检查可选mod-project.json的项目选择/程序集输出及允许名单。外部社区资料按 [参考边界](../../../../docs/community-references.md) 选择版本匹配条目，不因文档宣称已支持而跳过发行验收。

已提取的角色/资源/外观等专职Skills及共用内容契约见 [功能提取清单](../../../../docs/community-skill-extraction.md)。升级时按受影响功能同步参考字段、绑定、路径与验收边界；不必把所有社区章节带入每次迁移，也不将未运行的提取线索标为新版本实测。

同步核对Wiki的 [内容接入配方](../../../../docs/wiki/0.30.0/content-authoring.md)：注册键/资源内部名/运行键、Initialize注册冻结时机、Packet关联与Mod解锁条件、宿主骨架与Companion路线、创建数据覆盖及批处理观测、护具字段和地图拓扑校验。用新版发行包重验受影响最小链，不把旧版仅复用原外观的结果扩大为新动画或新脚本兼容。

外部动画管线同步核对 [动画导入Wiki](../../../../docs/wiki/0.30.0/animation-import.md)、reanim-import及reanim_dat.py：DAT布局、内嵌图集、片段区间、数据加载入口、独立部件/跟随与渲染路径。保留经典来源PAK/GBK资料的独立摘要，不把宿主更新当成原素材版本变化；宿主数据兼容仍须新版发行实际播放验证，不能只检查解码工具通过。

已有植物复刻还需同步plant-recreate的行为依据与 [动作/发射绑定](../../../../docs/wiki/0.30.0/plant-recreation.md)：事件派发及索引、检测几何、角度/行偏移与跨行碰撞、角色/预览场景Owner、正常卡片与费用冷却。`pvz-*`来源工具不随宿主变更任意改来源事实；`pvzhe-*`接入资料则按新版发行重验，保留近似与未测边界。

复刻流程还需同步[生产与移动](../../../../docs/wiki/0.30.0/production-and-locomotion.md)和mod-guide共用行为方案：导出器版本/控制媒体、重复层映射、实际根运动采样、循环/啃食/死亡、目标高度、状态生产及暂停计时。重新生成受影响的旧转换产物并在新版发行验证，不以原始DAT矩阵或声明片段存在替代运行结论。

涉及音频时同步audio-edit与[音频Wiki](../../../../docs/wiki/0.30.0/audio.md)：流/方案键、播放参数与总线、场景停止/释放、有效引用和恢复所有权；只验证播放器不宣称设备听感。HostProbe新增发现及methodDetails只表示元数据，类型加载诊断不为空时不得写成完整枚举。

涉及卡池与种植时同步[卡池Wiki](../../../../docs/wiki/0.30.0/card-pools.md)及plant-create的card-access参考：自动装卡的数量/容量分支、原版入场/选卡完成时序、地形与预置对象、单格/多格占位服务和配置类型。可选案例分开重验本体与普通入口，不以旧实验通过代表新版全部关卡。

分体/外部动画还需同步核对[挂接与播放契约](../../../../docs/wiki/0.30.0/animation-import.md#分体动画跟随坐标与动作播放)：层名到新层号、参考逆变换、parent/跟随/插层、预览复制引用、区间端点、SetAnimation参数和timeScale、动作完成与原版组件的切换所有权。新版按完整周期与动作往返重验，不沿用旧单帧或业务计数证明动画。

动画兼容路径还要复核PackedScene实际保存的Storage属性及实例化后运行开关，按需要在受限实例生命周期恢复；节点位姿与PNG/实际渲染分开验收，不将旧节点运动结果直接当作新版画面通过。

涉及移动炮口时，同步复核动作/发射Wiki的插槽层编号语义、offset变换顺序、Marker路径及创建时机；出生位置分布与速度方向分别验收，不能只检查发射数量就沿用旧对位结论。

涉及攻击预览时同步attack-preview、[网页流程](../../../../docs/attack-web.md)、attack_web/attack_recipe工具与origins.json预设：recipe及composition树/反馈/编译schema、嵌套倍率叠加与各组独立周期、仅查看隔离、transaction身份校验、草稿恢复、导出/实现摘要漂移和本地HTTP交接；预设按新发行重新采样并更新来源/DLL摘要，不能只替换版本字段。旧复杂编排不静默降级为网页模板。旧Tk攻击GUI已删除；保留既有复杂设计，超出网页范围时由AI分析差量修改。共同核对：默认地图资源键、透明角色捕获、参考姿态/图内原点与缩放、PCK/DLL/自有Mod摘要绑定和缓存失效。预览数学模型不自动等于新版宿主物理，确认方案的能力映射仍按受影响弹道专项重验；保留仅用户明确自定义才打开、持续等待而非60秒结束的调用约束。

攻击方案编辑器同步会话/方案schema及旧方案迁移，保留组/单发射项ID、时间轴、相对网格、地图触发区域和跨轮生命周期。已有design/attacks设计不随新版素材重新初始化；核对实现摘要漂移、直线追踪强度、抛物线快照及射线映射。新版用原版单发豌豆重测弹速/位移与出弹节奏，分开保存标称配置和实测波动，不继承旧300/1.5常量；用户方案实际速度/秒数不自动重标定。逻辑行、追踪参考点与碰撞另按新版发行复核，预设不是通用宿主SDK。

攻击预览抛射基准还须核验最终注册配置的catapultHeight、出生z/地面位置、飞行时间解算及离散运动；对照Wiki玉米投手参考更新host_catapult_reference及方案中的版本化catapultProfile，不用遗留同名tres代替实际配置，旧版规则身份不可直接盖成新版；有语义迁移时保留编排与原文件、标明轨迹变化并重新确认。

自有制导还须复核实际检测几何与目标资格、目标坐标、批处理槽位重用和更新时机。原版直接转向与编辑器有限纠正不是同一契约，不能升级时以开启追踪标志替换弱制导。分开验目标获取、实际转向/弹速与真实命中，暂停、来源死亡及离场结论分别保留；同步发射Wiki和character-fire参考，不将案例适配器当成通用SDK。复开/仅查看仍遵循[会话协议](../../../../docs/attack-web.md#草稿继续编辑与仅查看)，不得沿用旧确认覆盖设计。
