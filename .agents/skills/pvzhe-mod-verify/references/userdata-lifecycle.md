# 测试用户数据生命周期

适用：验证前准备隔离user://、测试结束整理、排查Godot用户目录膨胀。输入：本项目运行记录、实际user://、当前进程及保留需求；输出：逐目录归属、清理预览和归档/回收结果。默认只读盘点；要求更新指导不等于要求删除本机历史目录。

## 路径与归属

- Windows标准Godot用户数据根可从当前进程的`APPDATA`解析，不拼接盘符、用户名或假定用户配置在系统盘。它只是查找入口，不是删除目标；自定义user目录、便携版或重定向位置以宿主实际`user://`为准。环境变量缺失时查实际配置，不回退猜路径。
- 当前`tools/runtime_test.py`每次生成随机应用名并关闭custom_user_dir，在系统Godot用户数据根下创建隔离目录；将路径记入本轮`userdata-path.txt`及`identity.json`的userdata字段（启动前构建身份记录阶段）。当前工具没有用户目录自动回收功能，`runtime_storage preview/clean`仅处理工作区的可重建发行副本，不能声称它已清理user://。
- 从本项目明确的运行记录反向定位候选；记录项目、run-id、发行/包身份、目录、用途及保留状态。名称含Test/随机串、修改时间或体积均不能单独证明归属；历史记录缺失、其他项目的测试目录、日常用户目录及玩家接管使用的目录一律跳过。记录本身也需核对，不能盲信文本中的路径即执行删除。

## 新测试避免无限积累

启动前登记本轮目录及用途。条件兼容时复用已确认的隔离测试资料；干净初始状态、读档测试、不同版本/内容身份需要分开，不为减少目录数共用日常存档。当前工具默认新建目录，不支持的复用/自定义路径不能只改记录冒充已实现；修改驱动或PCK配置后核对实际user://再使用。

后续实现项目内测试资料时可放忽略提交的`.work`下，但必须验证宿主实际路径及隔离性，不能以启动工作目录位于项目内推定存档也在项目内。独立证据目录与用户资料分别登记，重复启动不要求重复建档。

测试结束优先保存运行证据、故障现场和必要资料；可回收的测试数据及时处理，不保留无限匿名目录。跨进程恢复、玩家试用、未解决故障或复现基线标为保留，记录原因；下次整理重新核对，而非按固定天数强删。

## 清理门槛：逐项允许，无法证明则跳过

1. **只读预览**：列出候选的规范化绝对路径、来源运行记录、文件类型/大小、运行/保留状态与计划动作，保存在本项目`.work`证据中。禁止用名称通配符生成递归删除命令，禁止针对用户数据根或其共同父目录操作。
2. **校验边界**：实际目标必须是已确认的单个测试目录或其明确允许文件，且与记录及预览一致；检查所有路径段和待处理子树的符号链接、junction及其他重解析点。遇到链接、越界、路径不一致或归属不明就跳过，不跟随链接。`.work`内路径也不能免除检查。
3. **停止写入**：核对目标游戏/测试进程及会话已结束，包含工作区外启动的进程；仅检查项目锁或等几秒不够。进程归属或活跃状态无法确认时保留，不杀玩家正在运行的游戏来清理。
4. **保护数据**：玩家存档、设置和Mod不作为缓存。测试产生的资料也先区分可复现夹具与人工试用成果；未知文件保留。必要日志、截图、报告、包身份及测试恢复资料复制到明确归档目录并核验清单/摘要后才考虑移除原副本；复制失败或缺项立即停止。不把移动到别处当作免除存档保护的办法。
5. **执行与复核**：只能处理预览中已证明属于本项目、无保留需求且已归档或可重建的明确项目。执行前再核对路径/内容/进程无变化；使用同一文件操作机制及精确路径，不跨shell拼接删除。整个测试目录只有在所有内容均满足门槛后才可移除；否则只清理明确文件，保留目录。记录实际动作、跳过原因及归档位置，确保非目标目录未被操作。

清理授权不能替代以上归属和边界证明。证据不足时保留并说明缺项；只有确实需要玩家判断资料用途时才询问，不要求玩家辨认技术目录名。这里定义人工/AI操作流程，未提供自动用户目录清理器，不把“文档检查通过”写成“清理工具安全验收通过”。
