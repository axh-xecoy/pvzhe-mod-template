# 验证执行策略

适用：自定义功能验收、失败后的重验、模板指导更新后的复核。输入：需求、实际变更、发行/包身份、已有证据；输出：本轮用例、分项结论、失败阶段及下一步。不要求玩家写测试计划，不为简单功能重建整套工具链。

## 启动前明确本轮能获得什么

先按[测试会话准备与复用](test-session.md)处理隔离环境的失焦暂停，并安排本次进程的整批采集及重置边界；不是每个断言各启动一次游戏。首次失败需要哪些状态也在启动前准备，避免失败后只为补日志再跑完整导航。

由 AI 在本地验证记录写一张简短用例卡，普通小功能可用一段话；向玩家简短说明本轮在测什么及实际会变化的条件，不逐条请求批准。

```text
用例/目的：验证运行中改变窗口宽高比后的按钮显示与命中
变更：布局映射代码；不是报告格式
身份：发行摘要、包/DLL摘要、夹具/检查器版本
前提：目标对局已就绪、卡槽数及模式已核实、无阻塞模态
操作：同一局改变窗口尺寸，等待重排，再检查显示并点击
预期：参考位置保持用户意图；屏幕矩形和命中随宿主变换
证据：实际窗口尺寸、内容区、显示/点击结果、就绪及失败截图
失败处置：记录最早失败阶段；未进入点击步骤不判业务失败
```

关键结果必须进入能使本轮失败的断言/判定，不能只打印hit/miss、计数或成功标记；未采到证据记未验证，不默认通过。对新增或修改的关键判定，离线注入一次失败结果或缺失证据，确认不会仍输出整体通过。

每条关键断言要回答“什么错误会使它失败”。新增关键产物检查时按风险选取损坏包、缺项或错误身份等负例，确认检查器确实拒绝；期望来自需求/独立基线，避免与实现共享同一个被改变量，或只查源码而未核对实际产物。例如参考画布矩形一致能发现位置错误，不能单独证明窗口适配；画布不变时反复换启动分辨率并检查同一个矩形，不增加缩放证据。模式、槽数、动态事件、阶段和窗口变化是独立维度；选择需求相关的边界组合，不机械运行完整笛卡尔积。用例前核实实际条件，单卡不代表满槽，设过参数不代表模式已应用。

## 采集、判定、报告分别执行

自定义采集可复用`tools.runtime_test.test`的显式driver_code/package_path/runtime_dir/user_args/required_markers接口；多Mod测试可显式传additional_packages并记录其包身份；它绑定本轮包和DLL摘要、保存失败日志/截图，检测ERROR/SCRIPT ERROR及展示故障后停止。调用方仍需独立构建成功、整轮锁和业务断言，不能并行覆盖输入；可参考SuperGatling/verify.py。已有日志用`python tools/runtime_diagnostics.py --log '<本轮日志>' --require '<业务完成标记>'`离线检查，缺结果或有宿主错误均拒绝。日志检查不是鼠标/画面或包加载证明；未知warning仍需人工分析，不把未命中规则当作无问题。

设计自定义驱动时保留三个可独立调用的步骤；可以是已有脚本中的函数，不必须增加框架或新命令：

1. 采集：运行当前包，输出原始日志、截图、实际条件和退出码。
2. 判定：读取指定轮次证据，检查身份、前提和断言，不启动游戏。
3. 报告：根据分项判定生成报告，不隐式重新构建或运行游戏。

修改检查器或报告代码，先用已有日志离线执行，覆盖成功、缺证据和未观测分支。Python语法检查只能发现语法错误，不能代替执行有变量顺序/分支的报告逻辑。离线重判保留原采集轮次及包身份，另记检查器版本；它不是当前新包的运行证明。游戏行为/采集条件有变化，或旧证据缺必要观测时，才补采受影响用例。

## 按实际变更选择重验范围

| 变更或失败 | 优先动作 |
| --- | --- |
| 报告变量、日志解析、成功文案 | 用指定旧日志离线重判；不启动游戏检查报告代码 |
| 编译/清单/打包错误 | build/check并核验摘要；失败停止，不运行旧包 |
| 按钮位置、锚点或输入映射 | 定向布局/命中；窗口适配在同一进程内切尺寸可覆盖时无需逐尺寸重新选关 |
| 暂停、阶段刷新或业务命令 | 定向进入相关阶段及恢复/业务结果，保留真实宿主操作前提 |
| 发行版变化、共享生命周期变化或最终发布包 | 按影响范围回归；最终包普通启动与适用功能验收仍保留 |

一次进程可顺序采集多个互不干扰的条件；会改变存档、清空对象或污染后续前提的操作须重置场景/夹具，必要时重启。仅省启动次数不能成为跳过隔离或正常发布验收的理由。保留已经通过且身份/条件匹配的证据，不为同一解析修复再跑全部加载、选关、暂停和业务。

## 每轮证据独立，运行期间不争用产物

证据放 `.work/verification/<run-id>/`，记录用例、发行/PCK、包/DLL摘要、夹具/检查器版本、参数、实际模式/槽数/窗口和步骤结果。失败轮也保留；汇总报告只能显式引用这些轮次，不能把原目录遗留的 verification.json 当本轮结果。

先成功 build/check，再复制本轮包与必要测试文件到独立运行目录并核验安装摘要；本轮使用的输入保持不变。共享 bin/dist、安装目录、游戏窗口、存档或证据目录的任务串行执行。后台验收未结束，不重新构建/覆盖其输入或再启动会争用焦点的游戏。确需并行时完整隔离且证明不争用；独立标签/日志文件不足以保证隔离。

模板内置 runtime_test 的CLI锁仅覆盖对应示例调用，自定义脚本直接导入函数不能假定继承整轮锁；需要在自定义驱动入口覆盖整轮共享资源，或顺序等待任务完成。构建后摘要核验不能代替运行期间输入隔离。

过滤输出不改变失败处理：PowerShell检查每条命令的LASTEXITCODE；Bash用pipefail并显式失败即停止或检查退出码。pipefail后使用分号仍可能继续运行。保留完整日志再查看，不以tail最后几行定位根因。

## 最早失败阶段与重试条件

区分产品实现、夹具/检查器和环境前提。先记录当前阶段、完整日志中最早的宿主错误（不只自写断言）及状态。Running等阶段标记不能代替关键依赖实例就绪；列表构造/加载结束也不能代替操作接收方已经开始等待，导航或选择的事件需在实际可操作阶段触发，版本例见[卡池时序](../../../../docs/wiki/0.30.0/card-pools.md)。依赖失败产生的零值不应被当作业务算法缺陷。交互失败按“输入送达→控件收到事件→点击回调→业务结果→相关表现”定位，悬停不等于点击成功，回调执行不等于完整效果。第一次命中失败尽量同时采集输入入口、坐标空间/变换、按下释放顺序及帧/时间、悬停对象、焦点、显隐/禁用/模态、实际收到的事件与回调；不能由hover为空就认定焦点是根因。条件可恢复时优先在同一场景定向诊断，下一次改变有依据的因素，而非重跑全部导航或同时乱改坐标与入口。

合成输入的同帧/分帧时序按当前宿主与控件实测，不固定一种为通用要求。一个方案成功只证明对应条件下可行，不能解释另一方案失败的原因；因果结论需控制其他因素的对照。系统鼠标或截图服务不可用时分别报告环境限制，不把合成输入的成功改写为系统验收。暂停验收用真实宿主流程，不修改内部标志制造等价假象；测试前提未成立时不把业务判为失败。

对象证据要匹配宿主实现：弹丸/角色可能使用批处理或保留视觉节点，场景树枚举为空不能单独判定未生成；优先组合宿主事件、身份、有效值和实际表现。事件中的配置内部名也可能不同于注册键，先记录真实值再设过滤器；检查器因错误名称漏收时先修正观测，不能改玩法迎合错误断言。失败路径同样收集日志/截图，不能只在进程返回成功后归档。

目标就绪后先保存基准截图/状态，在关键变换后保存证据，失败处尽可能补拍；不能把截图只放在所有断言之后，也不能为“早点有图”在加载/重排未完成时捕获正式背景。预览准备按 [捕获协议](../../../../docs/resource-cache-and-capture.md)。

统一阶段等待、驱动退出、进程超时和宿主帧数限制，记录究竟由谁结束。帧数不是固定秒数。超时先核对完成条件与最早停止点，不同时盲目增加所有超时。

重跑前写出相对上一轮的修复、条件变化或新增观测，以及预期能区分哪种原因。同一断点连续两轮仍未定位，先暂停完整回归并分析已有证据、增加定向诊断；不是停止整个开发或默认向玩家索取技术答案。仅“再试一次”不足以启动整套。偶发环境问题可有限重试，记录原因及次数；仍不满足前提则标为未验证，不随机点击或无限启动。

## 分项结论与证据强度

报告逐项标为通过/失败/未验证，列出实际窗口、模式、对象、入口方式、包摘要和证据轮次。入口方式区分人工/系统鼠标、经视口派发的合成输入和直接节点信号（含Pressed、GuiInput）；直接GuiInput只证明处理逻辑，不证明GUI命中、遮挡或捕获链，日志字段与实际调用一致；误标时纠正对应报告与可生成该字段的记录代码，保留历史说明。跨轮可补充覆盖，但不能拼成未实际执行的同一条链；某尺寸点击成功不等于另一个尺寸也成功。标记出现不等于通过，要检查数值、前提、错误及未观测标记；缺交互证据时布局可通过，交互仍未验证，整体不能写全部完成。

窗口适配区分参考画布位置、启动时不同尺寸、运行中改变尺寸和连续拖动缩放。按玩家需求执行，默认不要拿启动分辨率变化替代运行中重排；设置尺寸不声称人工连续拖动。核对实际尺寸及重排稳定，检查X/Y、宽/高、内容区偏移/裁剪与缩放后的点击。期望变换由已确认宿主策略/内容区或原版参考控件建立，不仅从待测按钮的实际宽度反推期望缩放再自证。

事件引起对象增减时，记录本次命令目标身份及确认结果；较早的总数快照不能当作调用时目标数，归零也不能单独证明按钮导致死亡。报告“没有触发方式/尚未验证”，不能写“理论上不可能”；达到当前槽数上限不等于无限增长。Wiki规则是有条件的指导，先核对证据再改实现，不能因“TopLeft非通用方案”就强制改锚点。可复用结论按 [Wiki维护](../../../../docs/wiki/maintenance.md) 记录，不复制试错流水。

动画类需求将运动/部件关系与业务分项验收：覆盖完整周期及动作往返，保留连续画面、实际位姿变化、首末帧/速度/完成事件。帧号推进不证明画面或挂接正确；条件允许时对关键运动断言做断开绑定等负向对照。CPU节点位置和GPU渲染位姿不必相同，按实际后端取证，不能为检查器方便默认切后端。版本例见[分体动画](../../../../docs/wiki/0.30.0/animation-import.md#分体动画跟随坐标与动作播放)。

画面运动断言与节点断言分别报告：节点X变化可能未反映到最终图像。若追加图像门禁，整体结论必须合并运行和图像结果，不能只读取运行assessment.json；保存校准前提及能拒绝旧错误画面的反例。切换后端或运行参数的对照先确认实际实例/实际配置已生效，样板值和打包前设置不等于运行条件。

攻击方案将编排出生、实际运动和命中/伤害分开验证；转向或发射事件不证明碰撞生效，来源死亡后仍在飞行也不证明仍能伤害。用原版控制弹药时，隔离其命中，避免它替新攻击满足断言；护具命中次数与本体扣血分别记录。测试Hook同样受启动注册冻结约束，在初始化订阅、在场景中切换采集条件，不到运行中才临时注册。

拖拽布局另验取消/无变化不提交、始终右锚定、拖动期间窗口缩放、左键业务与模态、同用户跨进程恢复；反馈按当前包DLL/会话/Mod/控件过滤，不因同名日志事件采用其他Mod位置。合成鼠标若在夹具开启GuiEmbedSubwindows须明确记录，该条件不进入生产Mod，也不替代原生窗口系统鼠标实测。

独立证据不等于独立游戏全拷贝：游戏环境按.game/current与old两槽管理，复用current/runtime且串行持锁；每轮保存驱动、包身份、日志、截图和可恢复测试PCK补丁。清理及失去更早基线后的恢复规则见[本地环境](../../../../docs/game-environment.md)，不能删除失败报告来换取通过。
