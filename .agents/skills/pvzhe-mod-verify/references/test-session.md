# 测试会话准备与复用

适用：自动化进入对局、采集动态行为或交接玩家试用。输入：当前发行身份、隔离 user://、本轮包和用例；输出：环境状态、分步骤证据与仍需重启的原因。具体游戏设置路径查当前版本 Wiki，不把环境处理加入发布 Mod。

## 先处理失焦自动暂停

当前0.31发行的开关为`Backgrounder=true`（允许后台运行），GameSaveManager读写方式、自动持久化注意事项及生效条件见[当前版本静态核验](../../../../docs/wiki/updates/0.31.0.md#自动化测试失焦暂停)；不同版本先核对，不复制猜测的设置文件。该路径尚不能代替实际失焦验收。

1. 自动化对局验证默认关闭隔离测试环境的失焦自动暂停。核对当前发行的设置入口、实际读取对象及生效时机；优先使用宿主设置，不猜设置键或直接修改战斗内部暂停标志。记录原值、测试值及作用范围；重建测试资料或设置被重新加载后重新检查。
2. 在对局已就绪后记录一次失焦前后状态：阶段、战斗/场景树暂停、阻塞弹窗及逻辑计时或对象推进。读回开关不等于行为通过；若尚未验证失焦，明确标为设置已应用、行为待核验。后台降帧与暂停分别诊断，不用墙钟等待直接推定游戏计时推进。
3. 不循环抢焦点、关闭任意弹窗或强制取消所有暂停。手动暂停、模态、结算及联机暂停仍遵守宿主规则；暂停用例单独按目标条件设置并恢复。确无已确认的禁用路径时，先做一次定向发行分析/运行诊断，不用多轮完整启动碰运气。
4. 只改隔离环境，不改玩家日常设置。人工交接说明失焦继续运行的状态；临时改动在会话结束恢复，明确专用于自动化的测试配置可保留并记录。系统鼠标命中测试仍可能需要前台，禁用暂停不代表可以后台真实点击；不要持续占用用户鼠标或抢回焦点。

## 每次启动都带着采集安排

启动前在本轮记录列出：需要运行才能回答的问题、用例顺序、每项就绪/成功条件、必要观测和结束条件。简单任务用几行即可，不创建庞大的测试管理框架。

- 同一发行、同一已加载包及可恢复前提下，合并布局切换、窗口缩放、重复操作、阶段变化等相关采集；先观察和非破坏检查，后执行清场/结算等破坏状态的操作。分别记录步骤条件，不能把同一局的所有步骤当成独立初始状态。
- 一次失败即收集相关日志、截图及状态；优先继续当前场景定向诊断，其次重置夹具/重进关卡，再考虑重启。重置后重新核对用例前提，继续采集不依赖失败前提的项目；崩溃或关键依赖损坏时停止。
- 只有更换已加载程序集/需重启生效的配置、跨进程持久化、崩溃/不可恢复污染或最终无测试参数启动等需要时，才重启。记录相对上轮的变化与预期新增证据；宿主没有可靠热重载时，不以省启动为由继续测旧 DLL。
- 日志解析、断言和报告修改先离线重判已有证据。已通过且身份/条件匹配的证据继续引用，缺观测才补采；不为修报告重复加载、选关和执行同一业务。

会话结束汇总每项通过/失败/未执行、证据路径和必要的下一次启动理由。详细身份隔离、负例与重试边界沿用[验证执行策略](verification-strategy.md)，不另设机械的启动次数指标。
