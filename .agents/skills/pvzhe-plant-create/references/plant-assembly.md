# 植物最小骨架与入口

社区来源见 [提取清单](../../../../docs/community-skill-extraction.md)。先用原外观、少依赖基底、一个属性或行为完成最小链，再增加功能。

0.31新增多格外壳/严格居中能力，先核对[选卡与占位差异](../../../../docs/wiki/updates/0.31.0.md#选卡阳光与多格外壳)及发行能力声明；不把底座规则直接套到外壳，不为普通单格植物增加Footprint注册。能力键存在不代表全部平台/地图已经实测。

0.32增加卡牌`plantAudio`/`plantWaterAudio`与能力键`plant-placement-audio-v1`（未配置回退默认音效），并让预放置/读档按保存的左侧锚点只还原一行、拒绝被夹取到别处的Footprint。字段与分支见[种植音效与预放置](../../../../docs/wiki/updates/0.32.0.md#种植音效与预放置恢复)；引用旧音频键时按当前注册表核对，本节不把它当成已运行的音效或读档验收。

0.30优先沿用 [已验收的托管复用路线](../../../../docs/wiki/0.30.0/content-authoring.md)：完整宿主场景→自有配置/组件副本→新Character→复用CharacterSprite→新Packet→自有关卡入口。新身份不要求新C#子类。复制原卡时重新建立Mod解锁策略，不能遗留原版关卡解锁条件；只改变自有副本。

| 层 | 建立与检查的关系 |
| --- | --- |
| 角色配置 | 自有name/saveKey与注册Key关系、基础血量/费用/种植覆盖条件 |
| 卡片 | characterConfig指向正确对象，必要override不改变不相关卡片 |
| Scene | 完整宿主场景实例、config、sprite NodePath、必要metadata及组件继承 |
| ComponentSet | ParentSet、Components及实例覆盖；完整基底可能已有组件，不重复挂载 |
| Sprite | 自有精灵注册指向宿主外观或自己的资源，不复制原版贴图 |
| 托管伴随 | 如当前加载器要求CompanionOnly，声明类型/基类/构造与DLL实际内容一致 |

社区的“六个文件”是具体路线的产物，不是固定数量约束；没有必要的本地化或新外观文件无需凑数，必要依赖也不能因超过六个而省略。

**组件集不是可选装饰**：不显式覆盖 `ComponentSet` 时宿主沿用基底场景那份，而运行组件是按集内定义逐个创建的 ⇒ 本 Mod 新增的发射等能力**根本不存在**，且不拒包、不进诊断。所以"角色能走能掉血、就是一弹不发"时，第一件事是查组件集是否真的挂上（含 `ParentSet` 指向内置集、`Components` 只追加所需项）。机制与闸门见[组件集条目](../../../../docs/wiki/0.30.0/content-authoring.md)与[发射链](../../pvzhe-character-fire/references/fire-pipeline.md)。

**卡面与场上单位共用同一份外观资源**：卡槽/图鉴里的卡面就是该角色的 CharacterSprite（按卡片的动画偏移/缩放摆放），不是独立插画 ⇒ "只换卡面"或"只换场上"通常做不到。外观类需求的这一取舍要在动手前与玩家确认。

种植条件要查plantCover、卡片override及关卡限制的实际组合，不能把“基底可种”当成新植物可种。选择界面、目录或图鉴分别有卡库与解锁前提；只修改本Mod新增项，不默认debug全开或重建全卡库。

创建失败先区分包/注册、角色类型绑定、场景依赖、组件实例和入口。回退成原版对象不算新植物成功；发射链、动画、复制目标等专项问题交给相应Skill，不继续堆入此入口。
